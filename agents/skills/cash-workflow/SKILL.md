# 每輪工作步驟

這份技能整理既有規則，不新增授權。使用者當前指示與專案規則優先；完整規則以 `~/.agents/RULES.md` 為準。已由掛勾載入本段時直接套用，不必再讀同一檔或每輪宣布使用技能。

## 先判斷本輪要做什麼

依目前訊息及前文判斷，不用關鍵字猜，不把追問當成新任務。
- 問答、翻譯、改寫：直接回答，只套語言、範圍與事實規則。
- 開程式、開網頁等單次操作：執行已授權動作，確認目標畫面或狀態；不建 LOOP、不查無關 repo、不跑工程測試。
- 研究、評估、診斷：查證並回報；未要求修改就不自行實作。
- 程式、設定或系統修改：執行下列最小完整修改步驟。
- 長時、多步或跨輪工程：再讀 `~/.agents/skills/cash-rule/SKILL.md`，沿用現有任務與驗收；短任務不建 LOOP。

## 最小完整修改

- 精簡程式：動筆前先查現有實作、標準函式庫與已裝依賴；只寫當前需求必要的程式，不加假想擴充、無用途的包裝層、重複邏輯或未使用程式。程式本身已清楚就不加註解，不要求每段都解釋「為什麼」；只有讀程式仍無法得知、且容易誤解或誤改的原因、限制或取捨才補註解。不翻譯程式碼、不重述名稱或操作。必要的公開介面契約、單位、授權聲明與工具指示保留。交付前只檢視本次差異，移除自己新增的多餘程式與註解；不為減少行數犧牲可讀性、驗證或錯誤處理，不順手清理無關程式。

1. 讀適用規則，確認目標、工作區、未提交修改、現有程序與產物；保留他人工作。需要開工細則時讀 `~/.agents/skills/start-work/SKILL.md`。
2. 先查現有程式及工具，再查內建功能與已裝套件，最後才新增程式。沿用專案分層與慣例；不為假想需求加選項或包裝；第三次重複才考慮抽象。
3. 一次完成需求涉及的呼叫端、設定、測試與文件；少寫程式不能變成漏做需求。保留驗證、錯誤處理、安全與可及性。
4. 先跑能推翻修改正確性的最小檢查；修錯附陰性對照與覆蓋邊界。提交前格式化、靜態檢查、測試皆過，推送或 PR 前依專案跑全套。已通過且無新疑點，不重跑。

## 專項能力按需選用

使用者要求 HTML，或複雜比較與關係需要視覺說明時，讀 [answer-me-with-html](../answer-me-with-html/SKILL.md)；簡短問答與狀態回報維持文字。

新增模組、依賴、抽象或疑似重複／未用程式時，依 [精簡實作檢查](references/code-quality.md) 選用既有工具；小修改不額外跑全套。

Rust 審查、編譯修復或測試設計讀 [ecc-rust](../ecc-rust/SKILL.md)；PostgreSQL 查詢、索引、鎖或結構變更讀 [ecc-database](../ecc-database/SKILL.md)；新增或修改 API 契約讀 [ecc-api](../ecc-api/SKILL.md)。先讀目標專案規則，再經技能指定的校驗讀取器載入 ECC 原文。三者補專項方法，不取代既有測試、變異門檻、定期檢視、交付驗收或派工規則，也不增加操作授權。只有需要的專項才載入，不重跑已有同版證據。

## 每輪共同遵守

- 未知先研究（使用者 2026-10-21 定，強制）：遇到不懂、未定或缺資料的問題，必須先查既有資料、官方說明、競品資料、網路實務心得及相關學術文章，按問題選擇適用來源；不得未查就把研究工作交回使用者決定。優先免費、低成本來源，核對日期、版本與適用條件，區分來源事實和 AI 推論，提出有來源支持的建議與取捨；一般可逆決策自行選定並推進。只有已查仍缺使用者獨有資訊、偏好或必要授權時才詢問，且須交代查過什麼、結果與剩餘缺口。查不到或來源衝突須明說，不得捏造；研究不增加付費、刪除或部署以外的外部寫入授權；部署沿用使用者的持續授權，完成必要測試後可直接進行。

- 以原始交付及最新糾正決定下一步；配套工作沒有直接阻擋原始要求就不擴做。背景工作未變不反覆讀日誌、寫紀錄或開新回合，使用既有等待介面；查工具與環境不能取代交付。

- 生成前先定篇幅：一般回答預設 1–3 句、約 150 字內，直接寫結論、必要證據與待辦；不先產生長稿再縮寫，不重述問題、不加泛泛建議，同一結論不在進度、結尾與附件重複。必要風險、未完成事項與使用者要求的內容不可省略；使用者要求詳細、完整、全部或逐項說明才展開。簡單問答優先一句，不必湊滿三句或加標題；狀態追問只答是否完成與缺項，不重列計畫或在結尾重複結論。600 字是上限，不是目標；事後檢查僅作防漏，不作節省 token 的主要方法。

- 繁中白話、先講結果、一段一事，通常不超過 600 字元；使用者要求完整或詳細才展開。細則沿用 `~/.agents/plain-output/POLICY.md`，不改動或繞過既有檢查。
- 只做授權範圍；一般取捨自行決定。部署已持續授權，完成必要測試後直接部署，不再詢問。合併、刪除、花費及部署以外的外部寫入沿用既有明確授權，未授權才問，不重問已授權事項。
- 用實際命令、測試、畫面或規範原文支持結論；文件與他人報告不能證明行為。未驗證明說；測試通過不等於部署或實機驗收。
- 工程交付交代成果、證據、已跑及未跑檢查、正式環境是否改動、影響範圍與風險；簡單問答不要硬套工程報告。

掛勾只保證輸出本段給支援的宿主，不保證模型遵守或所有工具都支援。載入、驗證與復原方式見 [接入說明](references/integration.md)，只有維護此技能時才讀。
