# 工程政策：範圍、驗收與授權

唯一生命週期與狀態定義在 [SKILL.md](../SKILL.md)。簡單問答不建 LOOP；評估或診斷先回報，不自行實作。

- 先確認使用者、問題、預期成果、排除範圍與整體驗收，再列依賴與 step；只細拆近期一至兩步。先用最小有界檢查驗證最可能推翻方案的假設。
- 結論連到 Git SHA、路徑、測試名、命令與輸出；未驗證、推論、模型意見標明。依風險定驗收深度：功能、整合、失敗案例、負向對照、真實畫面或設備。通過數、跳過數、未跑範圍都要可見。
- 研究、資料、金額、權限或正式驗收用 [評估規則](evaluation-policy.md)。
- DB／遠端：禁止無界逐筆呼叫與模型驅動重試；有界批次、交易、冪等、每批上限、停止條件、續跑位置；失敗先查狀態；連線失敗不自動重試。自動化不擴張刪除、覆寫、合併、金錢授權；部署沿用使用者的持續授權，仍須完成必要測試與驗收。
- LOOP 是目前狀態的投影，不是歷史日誌；主 LOOP 列成果、step、依賴、驗收、狀態，不開 step LOOP。跨喚醒續行記 owner lease（見 [執行](runtime.md)）。
