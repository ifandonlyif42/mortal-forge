# 工作交接

讓沒有參與對話的人，能找到成果、理解尚未完成之處，並照第一個步驟繼續工作。「乾淨」指入口明確、檔案用途清楚、背景工作有人接管、沒有隱藏待辦；不以 Git 無修改作為完成標準。

本技能整合 TechWolf 的接手步驟與驗證結構，以及 4qan 的文件歸檔方式；來源、改動理由與 MIT 授權見 [來源與授權](references/upstream.md)。

## 查清現場

1. 讀專案規則及現有文件索引，確認本次目標、真正工作的目錄與分支。多工作樹時指出哪個是接手入口，不建立第二份任務或執行者。
2. 從對話、既有交接與任務紀錄找線索，再用程式差異、可打開的產物、測試輸出或實際操作查證。舊文件和 commit 訊息不是完成證據。記下時間、版本與檢查範圍；查不到寫「未查證」。
3. 按使用者能做的事情說明成果：原本如何、現在能做什麼、在哪裡看、實測到哪一步。檔案數、提交數與測試數不能代替成果。
4. 查未提交及未追蹤檔案的用途與歸屬；查本任務的背景程序、連接埠、排程、鎖及執行者。無法讀取時明說，不把查詢失敗寫成「沒有」。不要輸出憑證、環境變數值或完整敏感命令列。
5. 分開記錄未完成、失敗、執行中、等人與未查證。每項寫影響、停點、下一個動作及由誰或什麼事件解除；原因不明寫「原因無紀錄」。保留已否決方向及理由。

## 整理成可接手的環境

- 先讀再改。把已查證且需要留下的操作方式、決策或結果放回既有負責文件；設計文件有原稿規則時遵守，不改生成頁。已有內容只引用，不複製出第二套規格。
- 優先更新專案已有的交接入口；沒有才在實際接手目錄建立 `HANDOFF.md`，並於既有文件索引補入口。只改與本次交接直接相關的文件，不順便重構程式或修功能。
- 更新前保留上一版交接到 `~/.local/state/recall/reports/` 的本次獨立資料夾，避免覆蓋掉仍有用的停點。其他任務或他人未提交內容保留；無法安全合併時另存本次交接並連到原件。
- 列明現場「已整理、刻意保留、待處理」及原因。活躍任務、共用服務與歸屬不明的檔案不能為了收尾而停止、搬走或刪除。已有明確授權的清理才執行，先列目標與影響，完成後讀回；缺授權先完成其餘交接，列出精確待處理項。
- recall 本身不提交、推送、合併、部署、刪分支、花費或開始下一項功能。需要這些動作時依使用者另行授權處理。也不自行改寫全域規則、記憶或歷史 checkpoint。
- 若使用者只要查看或指定唯讀，只產出外部報告與交接副本，不改專案文件或程序，明確標示現場尚未整理。

## 交付與接手

依 [交接模板與 PDF 輸入](references/handoff.md) 填寫接手文件，不留空白佔位字。先寫成果與遺留，再寫操作步驟；Git、PR、CI 與部署只放最後的查證資料，分開標示，不互相推定完成。

1. 提供成果的實際路徑或網址、啟動位置與命令、所需條件及預期畫面。未執行的命令標「未實跑」，不可假裝入口可用。
2. 接手步驟由最先要做的具體動作開始；每步寫在哪裡操作、要做什麼、如何判斷成功。若有背景工作，提供已有的查看與接管方式，避免重開一份。
3. 用 PDF 技能與 `scripts/render_recall_pdf.py` 產生繁中橫式摘要；使用 `sections` 格式，成果、遺留、接手動作排在前面。通常 1–2 頁，細節連回交接原件；不得為湊頁數截掉必要內容。JSON 與 PDF 放在 `~/.local/state/recall/reports/` 的本次獨立資料夾。
4. 讀回所有改動文件，核對路徑與命令來源；以 `pdfinfo`、`pdftotext -layout`、`pdftoppm` 檢查頁數、可搜尋文字與每頁版面。重新檢查差異及程序狀態，列出實際改了什麼、仍保留什麼。
5. 最後用短句回報是否可接手、最重要缺項，附交接入口與 PDF。未清理、未測試、未部署不能寫成已完成。

下次要求從交接繼續時，先讀入口，比對目前目錄、版本、未提交修改、程序與產物是否仍相符；過期內容先修正。用一句話重述目標與第一步，再按當次授權繼續，不重做已驗證成果。

## 完成判準

- 人類不翻聊天就能回答：現在能用什麼、剩下什麼、去哪裡操作、第一步做什麼、成功會看到什麼。
- 交接文件中的完成說法都有實測證據或清楚的未查證標記；正式環境與本機結果分開。
- 現場每個相關未完成修改與背景工作都有用途、狀態與接手方式；待授權項目明列，未被藏起來。
- 只有報表格式或 Git 狀態通過，不算人類接手驗收通過。
