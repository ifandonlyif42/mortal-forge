# 線上 3D 素材製作

目標是降低「進引擎後合格的素材」成本，不是堆生成數量。沿用使用者已選的服務、預算與風格；研究和準備本身不授權付費、上傳私有概念圖或公開作品；部署沿用使用者的持續授權，仍須完成必要測試與驗收。

## 按需求讀取

- 比較服務、官方工具、作品與他人心得：讀 [來源與工具查核](references/providers-and-evidence.md)。價格與功能有查核日期，付費前更新相關項目。
- 規劃、省費、批次、UE 驗收：讀 [製作與成本](references/production.md)。
- 保存、斷線接續、去重、交接：讀 [保存與恢復](references/archive.md)，複製 [批次計畫](assets/batch-plan.example.json) 與 [素材紀錄](assets/asset-record.example.json) 到專案；範例不是可直接送出的廠商請求。

## 執行要點

1. 先分清研究、安裝、生成、整理、匯入哪個範圍。查現有素材庫、任務 ID、CLI 版本與已授權額度，避免重做。選一個官方入口，已有 CLI 就不另造 MCP／API 包裝。
2. 每件素材先定用途、參考圖、尺寸、鏡頭距離、可動部件與合格條件。核心角色與可進入建築不因預覽漂亮便視為可交付。低細節配置模型只有明確的佔位需求才可交付為佔位，不可冒充成品。
3. 網頁、API、CLI 實際認證路徑分開核價。點數不是美元；API access 不等於包含免費 API 點數。若官方頁互相矛盾，列出矛盾，以本帳戶實際計費頁／估價／帳單確認，不自行推定。
4. 付費前有具體批次範圍、幣別與總上限、候選上限及停止條件。沿用既有明確授權，不每次重問；沒有支出授權時只出計畫與離線檢查。額度未知、花費未入帳、前次送出結果不明時不啟動依賴該額度的新任務。
5. 優先先看形狀再做材質，但要先核對該端點是否支援分段及是否真的省費。只對入選者加高解析貼圖、整理網格、骨架與動畫；能在本機完成的尺寸、格式或簡單修正，不預設再次付費。
6. 預設一件一送、一個工作擁有者；每次送出立刻記 task ID。相同請求以內容雜湊比對。固定候選數是停止點，不是一定要花完的數量。未知結果不盲重送；細節依保存文件。
7. 成功後先完整下載並核對檔案，再評圖。原始模型和原始貼圖座標保留不覆寫。臨時下載連結不能當備份。所有後處理都產生有父版本的新修訂。
8. 通過實際鏡頭下的近景、背面、輪廓、材質與尺度檢查才進 UE 隔離測試地圖。角色另跑動作變形。匯入成功、圖片好看、工具宣稱 game-ready 均不等於驗收。
9. 分開報：原始下載、整理中、已匯入、UE 驗收通過、拒絕。用全部嘗試的花費及整理時間除以合格數；合格數為零就回報零合格與總支出，不算零成本。

## 已知會浪費費用的工具行為

- Tripo CLI 0.7.0 的非互動模式不等待內建確認；不要依賴它阻止支出。其 batch 預設可重試一次，保存的是作業結果；下載失敗或提交結果不明不可直接重跑整批。核對新版本後才放行批次。
- Meshy CLI 0.4.4 的 `make --max-credits` 只比對這次計畫估價，不是專案累計預算；文字輸入預設會接續材質步驟。需要形狀關卡時採明確分段請求或已查證的 `--stop-after-first`，每一步仍記帳。
- Meshy 一般 API 模型保留最多三天；已過期的下載 URL 重新查任務不會自動延長。下載完成與第二份備份讀回前不刪原始檔。
